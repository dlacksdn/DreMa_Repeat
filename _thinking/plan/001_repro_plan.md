# 001. 논문 재현 구현 계획

작성: 2026-09-18
논문: Dream to Manipulate (DreMa), ICLR 2025 — https://arxiv.org/abs/2412.14957
코드: https://github.com/dlacksdn/DreMa_Repeat (원본 `leobarcellona/drema_code` 포크)

---

## 사전지식

| 용어 | 뜻 | 비유 |
|---|---|---|
| **모방학습** | 사람이 보여준 시범을 로봇이 따라 배우는 것 | 요리 영상 보고 따라 하기 |
| **PerAct** | 시범 + 말로 된 지시("블록을 초록 칸으로 밀어")를 받아 로봇 동작을 배우는 모델 | DreMa가 가르칠 "학생" |
| **RLBench** | 로봇 과제 100여 개가 들어 있는 시뮬레이션 시험장 | 로봇용 문제집 |
| **CoppeliaSim** | RLBench가 돌아가는 로봇 시뮬레이터 프로그램 | 문제집을 펼치는 책상 |
| **성공률** | 과제를 시켰을 때 성공한 비율 | 시험 점수 |
| **증강** | 시범 1개를 돌리고 옮겨서 여러 개로 불리는 것 | 문제 1개로 변형 문제 여러 개 만들기 |

## 0. 무엇을 재현하나 — 목표 수치

논문 **Table 1** (시뮬레이션, 9개 과제 평균 성공률):

| 학습 데이터 | 성공률 |
|---|---|
| PerAct — 원본 시범만 | **16.0 %** |
| DreMa — 상상 시범만 | 19.1 % |
| **DreMa + 원본 (전부)** | **25.1 %** |

→ **재현 성공의 기준: "원본만" 대비 "전부"가 확실히 높게 나오는 것.** 정확히 25.1 %가 아니어도, 차이의 방향과 크기(+9 %p 안팎)가 재현되면 성공이다.

조건: 과제당 변형(variation)마다 시범 **1개**(최대 5개). 증강으로 총 약 800개 시범 생성. 카메라 **3대** 사용(손목 카메라는 렌더링 고장으로 제외 — README 명시).

**하지 않는 것**: 실제 로봇 실험(Table 4). 하드웨어가 없다.

## 2. 전체 그림

```
[RLBench + CoppeliaSim]  ──①──>  과제별 시범 1개 + 사진 200장
                                        │
```

## 3. 단계별 계획

### M1. 샘플 1개로 파이프라인 끝까지 돌리기  — 예상 1~2일

**목표**: 있는 샘플(`slide_block`)로 ③ 증강까지 실제로 돌아가는지 확인.

| 할 일 | 완료 기준 |
|---|---|
| `config.yaml`의 `source_path`를 실제 폴더명으로 수정 | 실행 시 경로 오류 없음 |
| Hydra 작업 디렉터리 변경 문제 확인·대응 | `assets/` 상대경로가 깨지지 않음 |
| `visualize: False`로 헤드리스 실행 | 화면 없이 끝까지 돎 |
| `generate_new_data.py` 실행 | `data/generated_data/.../episode*/` 생성 |
| 생성된 시범 확인 | 사진·pkl이 열리고, 에피소드 수가 1 + N (최대 37) |
| 궤적 갱신 스텁의 실제 영향 확인 | pkl의 관절각이 원본과 같은지 눈으로 확인 |

> 이 단계는 **GPU 필요**(렌더링). 시작 전 GPU 점유 확인.

### M2. 데이터 생성 환경 만들기  — 예상 1~2일

**목표**: 9개 과제의 원본 시범을 우리가 직접 만들 수 있게 한다.

| 할 일 | 완료 기준 |
|---|---|
| Python 3.8 컨테이너 생성 | — |
| CoppeliaSim 4.1 설치 (Ubuntu 20.04 기준 배포판) | `xvfb` 위에서 헤드리스 기동 |
| PyRep → RLBench 포크 → YARR 포크 설치 | `prepare_data_for_drema.py --help` 동작 |
| `slide_block` 1개 생성 테스트 | 저자 샘플과 같은 폴더 구조가 나옴 |

> **위험**: CoppeliaSim 4.1은 2020년산이라 22.04에서 Qt 라이브러리 충돌 가능. 20.04 베이스 이미지를 쓴다.

### M3. 9개 과제 전부 — 시범 생성 → 복원 → 증강  — 예상 3~5일 (GPU)

과제: close_jar, insert_onto_square_peg_larger, pick_and_lift, pick_up_cup, place_shape_in_shape_sorter, place_wine_at_rack_location, put_groceries_in_cupboard, new_slide_block_to_color_target, stack_blocks

| 할 일 | 완료 기준 |
|---|---|
| 과제별 변형마다 시범 1개 생성 (①) | 약 30개 장면 |
| 장면마다 `create_simulation.py` (②) | `output/` 완비 |
| 장면마다 `generate_new_data.py` (③) | 총 약 800개 시범 (논문 수치) |

> ②가 병목이다. 장면 하나에 물체 수 + 1회 가우시안 학습(7000 iter). 5090 기준 장면당 수십 분 × 30장면. **tmux + 로그 필수.** 체크포인트는 장면 단위로 남긴다(끊겨도 그 장면만 다시).

### M4. PerAct 학습  — 예상 1주 이상 (가장 오래 걸림)

**목표**: 3조건(원본만 / 상상만 / 전부)으로 PerAct를 학습한다.

| 할 일 | 완료 기준 |
|---|---|
| PerAct 컨테이너 구성 | 공식 저장소 설치 완료 |
| `prepare_data_for_peract.py`로 ④ 변환 | PerAct 입력 포맷 |
| **먼저 slide_block 1과제 × 3조건** | 논문 표의 slide_block 행과 비교 |
| 나머지 8과제 확장 | 9과제 × 3조건 = **27회 학습** |

> **가장 큰 비용.** 논문은 과제별 단일 학습이라 27회가 필요하다. 1과제로 방향이 맞는지 먼저 보고 확장한다. 저장 간격은 촘촘하게(CLAUDE.md).

### M5. 평가 및 비교  — 예상 2~3일

| 할 일 | 완료 기준 |
|---|---|
| HuggingFace `val.tar.gz`·`test.tar.gz` 다운로드 (29 GB, 10 Mbps라 8시간) | 무결성 확인 |
| RLBench에서 성공률 측정 | 과제별 % |
| Table 1 형식으로 정리 | `_thinking/`에 보고서 |

## 4. 알려진 위험과 대응

| 위험 | 어디서 | 대응 |
|---|---|---|
| 궤적 갱신 스텁 (관절각·손목카메라 원본 그대로) | M1 | 영향 실측 후 판단. PerAct가 `gripper_pose`만 쓰면 무해 |
| 손목 카메라 렌더링 고장 | M1~M4 | 논문대로 **카메라 3대**만 쓴다 |
| Hydra가 작업 폴더를 바꿔 상대경로 깨짐 | M1 | `hydra.job.chdir=false` 또는 절대경로 |
| **논문 τ=0.015 vs 설정 `threshold: 0.035`** | M1 | 어느 값이 논문 실험값인지 코드로 확인. 불일치 시 0.015로 |
| Radius filter (논문) vs Scharr (기본값) | M3 | `radius_filter: True`로 논문 조건 재현 |
| `lambda_normal` 미발동 | M3 | 복원 품질 영향. 논문 조건인지 확인 필요 |
| CoppeliaSim 4.1 ↔ Ubuntu 22.04 충돌 | M2 | 20.04 베이스 이미지 |
| 회선 10 Mbps | M5 | 대용량은 미리 tmux로 받아 둔다 |
| 공용 GPU | 전부 | 실행 전 `nvidia-smi` 확인, 점유 시 보고 |

---

## 5. 판단이 필요한 것

1. **M4 범위** — 27회 전부 vs 대표 과제 3~4개만. 시간이 몇 배 차이 난다.
2. **τ 값** — 논문(0.015)과 설정(0.035)이 다르다. 논문 조건을 따를지.
3. **M2 착수 시점** — M1이 끝나기 전에 병렬로 시작할지. (환경 구축은 GPU를 안 써서 병렬 가능)

## 요약

> **목표**: 9개 과제 평균 성공률에서 **원본만 16.0 % → 전부 25.1 %** 의 차이를 재현한다. 실제 로봇은 제외.
> **길**: ① 시범 생성 → ② 3D 복원 → ③ 증강 → ④ PerAct 학습 → ⑤ 평가. 환경 3개 필요, 현재 1개 완료.
> **순서**: M1 샘플로 끝까지 한 번(1~2일) → M2 생성 환경(1~2일) → M3 9과제 데이터(3~5일) → M4 학습(1주+) → M5 평가(2~3일).
> **가장 큰 비용**: M4의 PerAct 학습 27회. 1과제로 먼저 확인하고 확장한다.
> **당장 할 일**: M1 — 설정 경로 고치고 `generate_new_data.py`를 실제로 한 번 돌린다.
