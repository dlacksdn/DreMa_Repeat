## 2. 단계 순서 — "1과제 끝까지" 먼저

001과 달리 **과제를 넓히기 전에 slide_block 하나로 끝까지 간다.** 끝까지 한 번 가봐야 어디가 막히는지 안다.

```
A단계  slide_block 1과제        ← 여기까지가 핵심. 이것만 돼도 목적 달성
   M1  샘플로 증강 실행
   M2  CoppeliaSim + RLBench 환경 (평가에 필요)
   M4  PerAct 학습 2회 (원본만 / 전부)
   M5  평가 → 논문 48.4 / 62.0 과 비교

B단계  pick_cup 추가            ← 시간 남으면
   M3  시범 생성 → 복원 → 증강 (M2 환경 사용)
   M4  학습 2회
   M5  평가

C단계  close_jar 추가           ← 여유 있으면
```

**학습 조건은 2개로 줄인다.** 논문의 3조건(원본만 / 상상만 / 전부) 중 "상상만"은 핵심 주장이 아니다. **원본만 vs 전부**가 논문의 본질이므로 이 둘만 한다.

## 3. 단계별 할 일

### M1. 샘플로 증강까지 실행  — 1~2일 · GPU

| 할 일 | 완료 기준 |
|---|---|
| `config.yaml` 경로를 실제 폴더명으로 수정 | 경로 오류 없음 |
| Hydra 작업 폴더 변경 대응 | `assets/` 경로 안 깨짐 |
| `visualize: False` 헤드리스 실행 | 화면 없이 완주 |
| `generate_new_data.py` 실행 | `data/generated_data/` 에 episode 1 + N개 |
| 궤적 갱신 스텁 영향 실측 | pkl 관절각이 원본과 같은지 확인 |
| **τ 확인**: 논문 0.015 vs 설정 0.035 | 코드로 어느 값인지 확정 |

### M2. CoppeliaSim + RLBench 환경  — 1~2일 · GPU 불필요

001과 같다. **M1과 병렬로 진행**한다 (GPU를 안 쓰므로 겹쳐도 됨).

> slide_block 샘플은 변형 1개(초록 목표)뿐이다. 논문은 변형 4개를 썼다. A단계는 변형 1개로 가고, 부족하면 이 환경으로 나머지 3개를 만든다.

### M3. 추가 과제 데이터  — 과제당 약 1일 · GPU

B·C단계에서만. pick_cup → close_jar 순.

| 할 일 | 완료 기준 |
|---|---|
| 변형마다 시범 1개 생성 | 저자 샘플과 같은 폴더 구조 |
| `create_simulation.py` (3D 복원) | `output/` 완비 |
| `generate_new_data.py` (증강) | episode 1 + N개 |

### M4. PerAct 학습  — 과제당 2~4일 · GPU

| 할 일 | 완료 기준 |
|---|---|
| PerAct 컨테이너 (Python 3.8) | 설치 완료 |
| `prepare_data_for_peract.py` 변환 | PerAct 입력 포맷 |
| **원본만** 학습 | 체크포인트 촘촘히 저장 |
| **전부** 학습 | 〃 |

> 학습 1회가 며칠 걸릴 수 있다. **tmux + 로그 + 촘촘한 저장**(CLAUDE.md). GPU 점유 전 확인.

### M5. 평가  — 1~2일

| 할 일 | 완료 기준 |
|---|---|
| RLBench에서 성공률 측정 (2조건) | 과제별 % |
| 논문 수치와 나란히 표로 | `_thinking/`에 보고 |

> 평가 데이터(`val`/`test` 29 GB)는 논문의 평가 에피소드다. 10 Mbps라 8시간 걸리므로 **M2 시작할 때 미리 tmux로 받아 둔다.**
