## 2. 씨앗 재현 — B안(논문 조건) 성공

원본 시범에 저장된 **난수 상태**를 되돌려 RLBench 에서 같은 장면을 다시 만들었다.

| 시도 | 최대 오차 | 판정 |
|---|---:|---|
| 1차 | 2.56 mm | A안 ✗ |
| **2차** | **0.000 mm** | **B안 ✓** |

**1차가 틀렸던 이유 — 내 재현 코드의 결함**

> **[공학적 정의]** 원본은 `callable_each_step=NeRFTaskRecorder.take_snap` 을 걸고 수집됐다. 이 콜백은 기록 스텝마다 물리 1틱(`scene.step()`)을 **추가로** 돌린다(첫 스텝 51회, 이후 1회). 1차는 이것을 빼먹었다.
>
> **[비유]** 같은 악보(씨앗)로 **박자(메트로놈)를 다르게** 연주한 것. 음은 같은데 연주가 밀렸다. 박자를 맞추자 완전히 겹쳤다.

→ **RLBench 원본 시범을 128×128·5카메라로 복원**. 3D 복원 불필요.
(1차 결과도 `data/seed_replay/` 에 보존)

## 4. 학습 설정 — A 와 B 는 **데이터만** 다르다

실제 `config.yaml` 두 개를 `diff` 한 결과, 다른 것은 **데이터 경로·개수·저장 폴더 이름**뿐이다.

### 데이터

| | 모델 A (대조군) | 모델 B (실험군) |
|---|---|---|
| 구성 | RLBench 원본 1개 | 원본 1 + 증강 17 |
| 에피소드 | 1개 (90스텝) | 18개 (90 + 59×17) |
| **학습 표본** | **16개** | **186개** (11.6배) |

증강 17개 = 평행이동 6 · 환경회전 5 · 물체회전 6 (τ=0.015 통과분)

### 공통 설정 (논문 부록 L)

```
PERACT_BC · batch 3 · 100k 반복 · 5k 마다 저장(60개 보관)
LAMB  lr 0.0005 고정 · β=(0.9, 0.999)
카메라 front / left_shoulder / right_shoulder · 128×128
복셀 100³ · SE(3) 증강(이동 ±12.5cm, z회전 ±45°)
```

## 5. 논문과 다른 점 — 4개

| # | 항목 | 논문 | 우리 | 영향 |
|---|---|---|---|---|
| 1 | 원본 시범 | 4개(4색) | **1개(green)** | **가장 큼.** 데이터가 논문의 28 % |
| 2 | 깊이 필터 | radius outlier | Scharr | 포인트클라우드가 다름 |
| 3 | **배치** | 4 | **3** | 저자 기록: slide_block 은 배치 영향 +1.2 뿐 |
| 4 | GPU | A40 48GB | RTX 5090 32GB | 3 번의 원인 |

→ **논문 수치(48.4 % / 62.0 %)보다 낮게 나오는 게 정상.** 볼 것은 **"A < B" 방향**이다.

## 6. 결과

![학습 결과](20260925_2042_003_training_result.png)

### (a) 학습 손실 — B 가 더 높다

| 구간 | A | B |
|---|---:|---:|
| 0 ~ 10k | 3.66 | 5.30 |
| 90 ~ 100k | **0.57** | **1.00** |

### (b) 교차 평가 — 그런데 A 는 처음 보는 장면에서 무너진다

가중치를 고정(학습률 0)하고 서로의 데이터에서 손실을 쟀다. 95 % 신뢰구간이 서로 겹치지 않는다.

| | 원본 1개 | 증강 17개 |
|---|---:|---:|
| **모델 A** | 0.56 | **54.64** |
| **모델 B** | 1.33 | 0.91 |

**해석 3가지**

1. **A 는 외웠다.** 본 장면 0.56 → 처음 본 장면 54.64 (**98배**). 특히 회전 손실 38.4 — 방향을 전혀 모른다.
2. **B 는 고르게 배웠다.** 증강 17개를 0.91 까지 맞힘 → **증강 라벨이 서로 일관되다**(버그면 불가능).
3. **B 는 원본에서 A 보다 2.4배 부정확하다.** 원본이 B 표본의 8.6 % 뿐이고, 18개 중 **유일한 RLBench 렌더**(나머지는 가우시안 렌더)라서다.

> **[공학적 정의]** 학습 손실은 **본 데이터에 대한 적합도**이지 **처음 보는 장면에서의 성공률(일반화)** 이 아니다. 일반화는 평가 세트(M5)로만 잴 수 있다.
>
> **[비유]** A 는 **기출 1개를 외운 학생** — 그 문제는 만점, 숫자만 바꾸면 0점. B 는 **기출 18개를 푼 학생** — 연습 점수는 낮지만 새 문제에 강하다.

**남는 위험**: M5 평가 장면은 **RLBench 렌더**다. B 는 RLBench 렌더에서 더 약했으므로(1.33 vs 0.91), **렌더 방식 차이(도메인 갭)** 가 B 를 깎을 수 있다. DreMa 방법론 자체의 한계이며 M5 에서 드러날 것이다.

## 8. 다음 — M5 에서 정할 것

**평가 절차 (논문)**
```
val 40개로 체크포인트 21개씩 평가 → 모델별 최고 선택
→ test 50개 × 5회 → 성공률  →  A vs B 비교
```

**⚠️ 정해야 할 것: 색상**

평가 데이터는 4색이 섞여 있는데, 우리는 **green 만** 학습했다.

| | 전체 | green |
|---|---:|---:|
| val | 40 | **10** |
| test | 50 | **10** |

| 방식 | 장점 | 단점 |
|---|---|---|
| 전체 4색 | 논문과 같은 조건 | 학습 안 한 3색이 섞여 **둘 다 낮게** 나옴 |
| **green 만** | 학습한 조건 그대로 | 표본 10개뿐 (×5회 = 50회 시도) |
| **둘 다 집계** | 두 관점 모두 확보 | 평가는 한 번, 집계만 나눔 |

→ **둘 다 집계**가 추가 비용 없이 가장 정보가 많다.

## 요약

> **M4 가 끝났다.** 씨앗 재현이 오차 0.000 mm 로 성공해 **논문 조건(B안)** 으로 갔고, 환경 블로커 6개를 전부 풀어 **모델 A·B 를 같은 설정으로 10만 스텝씩** 학습했다. 논문과 다른 점은 4개이며, 그중 새로 생긴 것은 **GPU 한계로 인한 batch 3** 하나다.
> **학습 손실은 A(0.57)가 B(1.00)보다 낮지만**, 교차 평가에서 **A 는 처음 보는 장면에 98배 무너지고 B 는 고르게 적당**했다. 증강의 효과는 학습 손실이 아니라 **처음 보는 장면에서의 성공률**로 드러난다.
> **다음은 M5 평가**다. 평가 데이터에 4색이 섞여 있어 **전체와 green 을 둘 다 집계**하는 방식을 제안한다.
