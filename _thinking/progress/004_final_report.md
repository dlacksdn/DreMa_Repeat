---

## 한 줄 결론

> **로봇 시범 1개를 3D로 복원해 "상상한 시범" 17개를 더 만들어 학습시켰더니, 학습한 장면에서 성공률이 20 % → 96 % 로 올랐다.**
> 논문의 핵심 주장 — *상상한 시범이 로봇의 성공률을 높인다* — 이 같은 방향으로 재현됐다.

## 사전지식

| 용어 | 뜻 |
|---|---|
| 모방학습 | 사람이 보여 준 시범을 보고 로봇이 따라 배우는 방법 |
| 시범 (에피소드) | 과제를 처음부터 끝까지 한 번 해낸 기록 = 카메라 사진 + 로봇 손 위치 |

| 가우시안 스플래팅 | 수많은 반투명 점(가우시안)으로 3D 장면을 만들고 어느 방향에서든 사진처럼 그려 내는 기술 |
| 증강 | 가진 데이터를 변형해 학습 데이터를 늘리는 것 |
| τ | 상상한 시범의 검수 기준. 블록 최종 위치가 기대 위치에서 1.5 cm 안이어야 채택 |
| PerAct | 시범으로 배우는 로봇 모델. 장면을 100×100×100 칸으로 나눠 "손을 놓을 칸"을 고른다 |
| RLBench | 로봇 과제 시뮬레이터. 평가 장면도 여기서 만든다 |
| 경로계획 | 손을 목표 자세로 옮길 팔 관절 경로를 찾는 계산. 무작위 탐색을 쓴다 |
| 체크포인트 | 학습 도중 저장한 모델. 5,000 스텝마다 저장 → 모델당 21개 |
| 검증 세트 · 시험 세트 | 체크포인트 중 최고를 고르는 시험(40장면) · 최종 점수를 내는 시험(50장면) |

| PSNR | 복원 사진이 원본과 얼마나 같은지 나타내는 점수. 높을수록 비슷 (30 dB 이상이면 매우 양호) |
| %p | 퍼센트포인트. 두 비율의 차이 (20 % → 96 % 는 +76 %p) |
| 모델 A · 모델 B | A = 원본 시범 1개로 학습한 대조군 · B = 원본 1개 + 상상 17개로 학습한 실험군 |

## 1. 논문이 주장하는 것

> **[공학적 정의]** 모방학습은 시범이 많을수록 잘 되지만 사람 시범은 비싸다. DreMa 는 시범 장면을 **가우시안(겉모습) + 물리 시뮬레이터(움직임)** 로 복원한 "세계 모델"을 만들고, 그 안에서 **물체 배치를 바꿔 로봇 동작을 다시 실행**해 새 시범을 합성한다. 결과가 기대와 맞는 것(<abbr title="증강 검수 기준, 블록 최종 위치의 허용 오차 1.5cm">τ</abbr> 검수 통과)만 학습에 쓴다.
>
> **[비유]** 요리를 **한 번** 배운 뒤, 머릿속으로 "재료가 왼쪽에 있었다면?", "도마가 돌아가 있었다면?"을 상상하며 연습하는 것이다. 다시 배우지 않아도 실력이 는다.

**과제 — slide_block_to_color_target**: 빨간 블록을 지시한 색(green·blue·pink·yellow)의 목표판 위로 **밀어서** 옮긴다. 집어 드는 과제가 아니다.

**논문 목표 수치** (Table 1, 이 과제):

| 학습 데이터 | 성공률 |
|---|---:|
| 원본 시범만 | 48.4 % |
| 상상 시범만 | 54.4 % |
| **원본 + 상상** | **62.0 %** |

→ 재현 성공의 기준: **"원본만" < "원본 + 상상"** 이 같은 방향으로 나오는 것.

 + 손 궤적        물리 모델           로 바꿔 다시 실행       17개 통과          모델 B: 원본 + 17개       50장면

| 단계 | 한 일 | 결과 |
|---|---|---|

| 4단계 · 학습 | 원본 시범 재실행 + 모델 <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr>·<abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 를 같은 설정으로 학습 | 재실행 오차 0 mm, 각 10만 스텝 · 체크포인트 21개 |
| 5단계 · 평가 | 검증 세트로 최고 체크포인트 선택 → 시험 세트 | green: <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 20 % → <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 96 % |

(3단계 = 과제 9개로 확장 — 흐름 체득이 목적이라 과제 1개로 줄였다.)

## 3. 상상한 시범 만들기 (데이터 증강)

### 3-1. 입력 — 시범 단 1개

![입력 데이터](../Data_Analysis/20260914_1230_001_sample_data_overview.png)

- 카메라 200곳(④)이 장면을 **빙 둘러 찍은 사진 200장**(①) + 깊이(②) + 물체 구분표(③) + 로봇 손 궤적 90스텝
- 지시는 *"slide the block to green target"* → **green 1색뿐**이다

### 3-2. 3D 복원 — 진짜와 구분이 안 된다

![복원 품질](../Data_Analysis/20260919_1322_002_recon_quality.png)

왼쪽 진짜 사진, 가운데 복원본이 다시 그린 사진. 평균 <abbr title="복원 사진이 원본과 얼마나 같은지 나타내는 점수, 높을수록 비슷">PSNR</abbr> **32.2 dB**. 차이(오른쪽)는 물체 가장자리에만 얇게 남는다.
→ 복원이 정확해야 그 위에서 상상한 시범도 믿을 수 있다. **토대가 튼튼하다.**

### 3-3. 증강 3종 — 실제 학습에 쓴 것

![증강 3종](20261002_2050_004_aug_types.png)

![증강 3종 영상](../videos/20261002_2050_004_aug_types.gif)

| 종류 | 무엇을 바꾸나 | 채택 / 시도 |
|---|---|---:|
| 평행이동 | 테이블·물체 전체를 로봇 기준으로 ±15 cm 밀기 | 6 / 8 |
| 환경회전 | 테이블·물체 전체를 한 점 둘레로 30° 씩 돌리기 | 5 / 11 |
| 물체회전 | 목표판·테이블은 그대로 두고, 블록과 손 궤적을 **궤적의 마지막 손 위치(블록을 다 밀어 넣은 곳) 둘레로** 20° 씩 돌리기 → 다른 방향에서 밀어 오는 시범 | 6 / 17 |

- 로봇 손 궤적도 **같은 변환**을 받는다 — "옮겨 놓은 장면에서 같은 동작을 다시 해 본다".
- 위 그림 맨 윗줄 원본은 RLBench 렌더(선명), 아래 증강은 가우시안 렌더(약간 흐림)다. 이 차이는 [§4](#4-학습--모델-2개) 에서 다시 나온다.

### 3-4. 검수 — <abbr title="증강 검수 기준, 블록 최종 위치의 허용 오차 1.5cm">τ</abbr> = 1.5 cm

> **[공학적 정의]** 바꾼 장면에서 로봇 동작을 물리 시뮬레이션으로 다시 돌리면, 블록이 기대한 곳으로 가지 않을 수 있다. **블록의 실제 최종 위치**가 **원래 결과를 같은 변환으로 옮긴 위치**에서 <abbr title="증강 검수 기준, 블록 최종 위치의 허용 오차 1.5cm">τ</abbr> 이내일 때만 채택한다.
>
> **[비유]** 시범을 복사기로 36장 뽑고 **삐뚤어진 것은 버리는** 검수다. <abbr title="증강 검수 기준, 블록 최종 위치의 허용 오차 1.5cm">τ</abbr> 는 "얼마나 삐뚤면 버릴지"의 기준선이다.

![오차 분포](../Data_Analysis/20260919_1613_003_tau0_full_error_dist.png)

- **논문은 <abbr title="증강 검수 기준, 블록 최종 위치의 허용 오차 1.5cm">τ</abbr> = 0.015 m, 공개 코드의 기본값은 0.035 m** 로 서로 다르다 → 논문 값을 썼다.
- 근거: 채택률이 우리 **49 %**(원본 포함 18 / 37), 논문 이 과제 **41 %** 로 가깝다. 코드 기본값이면 92 % 가 돼 논문과 맞지 않는다.
- 블록 한 변이 5.8 cm 인데 1.5 cm 기준은 분포 한가운데를 자른다 → **눈으로는 성공한 시범도 꽤 버려진다.** 논문도 같은 기준을 썼다.

**채택 vs 탈락**

![채택과 탈락](../Data_Analysis/20260919_1549_003_tau015_sequence.png)

위: 채택(물체회전 −20°) · 가운데: 오차 2.8 cm 로 탈락(−100°) · 아래: 팔이 닿지 않아 40스텝에서 중단(+100°)

![탈락 영상](../videos/20260919_2148_rejected_objrot100.gif)

↑ 물체회전 +100° — 블록을 밀어야 할 지점이 팔이 닿지 않는 곳이라 동작이 중간에 멈춘다.

## 4. 학습 — 모델 2개

| | 모델 <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> (대조군) | 모델 <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> (실험군) |
|---|---|---|
| 학습 데이터 | 원본 시범 1개 | 원본 1개 + 상상 17개 |
| 학습 표본 수 | 16개 | 186개 |
| 설정 | **동일** — PerAct, 배치 3, 10만 스텝, 카메라 3대(정면·왼쪽 어깨·오른쪽 어깨), 128×128 | ← |
| 학습 시간 | 약 26시간 | 약 22시간 (65,000 스텝에서 한 번 끊고 이어서) |

→ 두 모델의 설정 파일을 비교해 **학습 설정은 데이터만 다름**을 확인했다 (단, 모델 <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 는 65,000 스텝에서 한 번 끊고 이어서 학습했다). 그래서 성공률 차이를 **추가한 상상 시범의 효과**로 본다. 다만 원본을 복제해 개수만 18개로 맞춘 대조군은 돌리지 않아, "시범 수가 늘어서"와 "상상으로 장면이 다양해져서"를 완전히 나누지는 못했다.

**원본 시범은 어떻게 준비했나** — 받은 원본에는 학습용 사진(128×128)이 없었다. 원본에 저장된 **난수 상태를 되돌려 RLBench 에서 같은 장면을 다시 실행**해 만들었다. 손 위치 오차 **0.000 mm** 로 완전히 같다.

![학습 결과](20260925_2042_003_training_result.png)

- **(a) 학습 손실은 <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 가 <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 보다 낮다** (90,000~99,900 스텝 평균 <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 0.57 · <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 1.00). 시범 1개는 외우기 쉽기 때문이다.
- **(b) 교차 평가** — 두 모델을 서로의 데이터에 넣어 손실을 쟀다. **<abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 는 처음 보는 장면(상상 시범)에서 손실이 54.6 으로 98배 폭증**하고, <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 는 어디서나 1 근처다.

> **[비유]** <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 는 **기출문제 1개를 외운 학생**이다 — 그 문제는 만점, 숫자만 바꿔도 0점. <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 는 **기출 18개를 푼 학생**이다 — 연습 점수는 조금 낮아도 새 문제에 강하다.

## 5. 평가 결과

**평가 절차** (논문과 같음): 검증 세트 40장면으로 체크포인트 21개를 모두 평가 → 성공률이 가장 높은 것을 고름 → 그 체크포인트로 시험 세트 50장면을 평가. 평가 장면은 DreMa 저자가 공개한 RLBench 장면이며 **4색이 섞여 있다**(시험 세트 50장면 중 green 10장면). 그래서 **전체 4색**과 **green 만** 두 가지로 집계했다.

### 5-1. 성공률

![평가 결과](20261002_2127_004_m5_result.png)

| | 모델 <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> | 모델 <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> | 차이 |
|---|---:|---:|---:|
| 선택된 체크포인트 (검증 세트 기준) | 85,000 스텝 | 80,000 스텝 | |
| **green — 학습한 색** (10장면 × 5) | **20 %** | **96 %** | **+76 <abbr title="퍼센트포인트, 두 비율의 차이">%p</abbr>** (95 % 신뢰구간 +48 ~ +98) |
| 전체 4색 (46장면 × 5) | 4.3 % | 21.7 % | +17 <abbr title="퍼센트포인트, 두 비율의 차이">%p</abbr> |
| 학습 안 한 3색 | 0 / 180 | 2 / 180 | |

- 표의 성공률은 **경로계획 난수 흐름 5가지**로 잰 값이다([§5-4](#5-4-주의--같은-장면도-결과가-바뀔-수-있다)). 표준 절차 그대로는 green <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 20 % · <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 100 %, 전체 4색 <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 4.0 % · <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 20.4 %.
- **<abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 는 green 10장면 중 늘 같은 2장면만 성공**한다. <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 는 10장면 모두 대부분 성공한다.
- (a) 를 보면 <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 는 체크포인트 21개 중 11개에서 green 100 % 지만, **0 %(40,000·70,000 스텝) · 10 %(90,000) · 30 %(65,000) 로 떨어지는 체크포인트도 있다.** 검증 세트로 고르는 절차가 중요했다.
- 성공률이 같으면 가장 뒤쪽 체크포인트를 고른다. <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 는 14개가 green 40 % 로 같아 85,000 이 선택됐다.

### 5-2. 같은 장면, 두 모델

같은 green 장면 29 를 두 모델에게 시켰다. **<abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 는 블록 근처까지 가지만 목표판에 올리지 못하고, <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 는 블록을 green 목표판 위에 올린다.** ([발표용 영상](../videos/20261002_2207_004_rollout_ab_ep29.mp4))
<abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 는 이 장면을 어떤 실행 조건에서도 실패했고, <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 는 긴 연속 실행에서 7번 모두 성공했다.

![pink 지시](../videos/20261002_2127_004_rollout_b_pink_11s.gif)

모델 <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 에게 *"pink 목표로 밀어라"* 를 시켰다. 오른쪽 pink 가 아니라 **늘 하던 green 쪽으로** 블록을 민다. 두 모델 모두 green 만 배웠기 때문이다. ([발표용 영상](../videos/20261002_2123_004_rollout_b_pink.mp4))

### 5-4. 주의 — 같은 장면도 결과가 바뀔 수 있다

> **[공학적 정의]** 손을 옮길 팔 경로를 찾을 때 RLBench 는 **무작위 탐색 + 10 ms 시간 제한**을 쓴다(`arm_action_modes.py`, `max_time_ms=10`). 그래서 **같은 모델·같은 장면이라도 실행 이력(앞서 몇 번 계획했는지)에 따라** 다른 경로가 나와 성공·실패가 갈릴 수 있다. 컴퓨터 속도(시간 제한)도 영향을 줄 것으로 추정하지만, 시간 제한을 바꿔 보는 실험은 하지 않았다.
>
> **[비유]** "10초 안에 꾸러미에서 맞는 열쇠를 찾아라" 시험이다. 같은 꾸러미라도 **어떤 순서로 집어 보았는지**(그리고 아마 그날 손이 얼마나 빠른지)에 따라 결과가 다르다.

| 발견 | 내용 | 대응 |
|---|---|---|
| ① 반복이 반복이 아니었다 | 표준 절차의 5회 반복이 **매번 같은 순서**로 돌았다. <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 는 5회가 완전히 같았고, <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 도 50장면 중 1장면만 달랐다 (전체 20~22 %, green 은 5회 모두 100 %) → 반복으로 난수가 거의 바뀌지 않았다 | 시작 장면을 0~4 로 바꿔 **난수 흐름 5가지**로 다시 쟀다 → <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 의 green 100 % → **96 %** |
| ② 짧은 실행에서 실패가 잦았다 | 새 실행의 첫 장면이나 4장면짜리 짧은 실행에서 <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 가 자주 실패했다 (장면 29: 짧은 실행 3/3 실패, 20장면 이상 긴 연속 실행 7/7 성공 · 장면 16: 짧은 실행 2/2 실패). 다만 표본이 적고 긴 실행끼리도 장면 16 결과가 갈려, 원인은 확정하지 못했다 | 우리 평가 수치는 전부 **긴 연속 실행**(PerAct 표준 절차)에서 나왔고, 각 실행의 첫 장면은 모두 학습 안 한 색이었다 → 이 효과가 green 수치에 직접 들어가지는 않았다 |

![같은 장면 실패와 성공](../videos/20261002_2152_004_rollout_b16_fail_vs_succ.gif)

↑ 모델 <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> · green 장면 16 — **같은 모델·같은 장면**인데, 첫 장면으로 돌리면 실패(왼쪽), 다른 장면 6개 뒤에 돌리면 성공(오른쪽)한다. 이 장면은 긴 실행에서도 7번 중 5번 성공한 경계 장면이다. ([발표용 영상](../videos/20261002_2152_004_rollout_b16_fail_vs_succ.mp4))

### 5-5. 논문과 비교

| | 원본만 | 원본 + 상상 |
|---|---:|---:|
| 논문 (4색 학습 · 원본 4개) | 48.4 % | 62.0 % |
| 우리 · 전체 4색 (green 1색 학습 · 원본 1개) | 4.3 % | 21.7 % |
| 우리 · green 만 | 20 % | 96 % |

→ **방향(원본만 < 원본 + 상상)이 재현됐다.**
전체 4색의 절대값이 낮은 이유: 시험 50장면 중 **40장면이 학습하지 않은 색**이다. 학습 안 한 색은 두 모델 모두 사실상 0 % 라, 전체 4색 성공률은 **green 장면 비율(약 20 %)이 사실상 상한**이다. <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr>(21.7 %)는 그 상한과 거의 같다 — green 2번 실패와 다른 색 2번 성공이 상쇄됐다.

## 6. 논문과 다른 점

| # | 항목 | 논문 | 우리 | 영향 |
|---|---|---|---|---|
| 1 | 원본 시범 | 4개 (4색) | **1개 (green)** | **가장 큼.** 학습 데이터 65개 → 18개 (28 %) |
| 2 | 과제 수 | 9개 | **1개** | 축소판 계획 (흐름 체득이 목적) |
| 3 | 배치 크기 | 4 | **3** | <abbr title="그래픽 처리 장치, 학습 계산에 쓰는 칩">GPU</abbr> 메모리 부족 (논문 A40 48 GB, 우리 RTX 5090 32 GB). 저자 기록상 이 과제는 배치 영향이 작다 |
| 4 | 깊이 잡음 필터 | radius outlier (3D 판단) | Scharr (2D 판단, 코드 기본값) | 포인트클라우드가 약간 다름. 논문 방식은 계산이 33시간이라 포기 |

→ 모두 의도한 차이다. 1·2번은 분명히 수치를 **낮추는 쪽**이고, 3·4번(배치·깊이 필터)이 어느 쪽으로 작용하는지는 확인하지 못했다.

| 환경 | DreMa 가 쓰는 RLBench 판본은 PerAct 학습에 못 쓴다 | 학습·평가만 PerAct 판본 사용 (두 판본의 과제 정의는 파일 단위로 동일 확인) |
| 환경 | RTX 5090 → 최신 torch·numpy 가 강제돼 2022년 부품과 충돌 | pandas 업그레이드, pyrender 1줄 보정 |

| 평가 | 컨테이너 공유 메모리 64 MB → 평가 프로세스가 죽는다 | 자식 프로세스 없이 직접 실행 |
| 평가 | 경로계획 무작위성 · 실행 이력 의존 ([§5-4](#5-4-주의--같은-장면도-결과가-바뀔-수-있다)) | 난수 흐름 5가지로 재측정 |

## 요약

> **무엇을** — DreMa 논문의 핵심 주장, *"시범 1개를 3D 세계 모델로 복원하고 물체 배치를 바꿔 상상한 시범으로 학습하면 성공률이 오른다"* 를 slide_block 과제 1개로 재현했다.
> **어떻게** — 시범 1개(사진 200장)를 가우시안으로 복원(<abbr title="복원 사진이 원본과 얼마나 같은지 나타내는 점수, 높을수록 비슷">PSNR</abbr> 32.2 dB)해 36가지로 바꿔 보고, 논문 기준 <abbr title="증강 검수 기준, 블록 최종 위치의 허용 오차 1.5cm">τ</abbr> = 1.5 cm 로 17개를 채택했다. 원본만(<abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr>) / 원본 + 17(<abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr>) 두 모델을 **데이터만 다르게** 10만 스텝씩 학습했다.
> **결과** — 학습한 green 장면에서 **<abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 20 % → <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 96 %** (+76 <abbr title="퍼센트포인트, 두 비율의 차이">%p</abbr>). 전체 4색은 <abbr title="모델 A, 원본 시범 1개로 학습한 대조군">A</abbr> 4.3 % → <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 21.7 % 로 논문(48.4 → 62.0)과 **방향이 같다.** 절대값이 낮은 것은 green 1색만 학습해 상한이 약 20 % 이기 때문이며, <abbr title="모델 B, 원본 1개와 상상 17개로 학습한 실험군">B</abbr> 는 그 상한과 거의 같다.
> **주의** — green 시험 장면이 10개뿐이라 효과의 정확한 크기는 불확실하다. 또 로봇 경로계획이 무작위라 같은 장면도 결과가 바뀔 수 있어, 난수 흐름 5가지로 다시 재서 보고했다.
